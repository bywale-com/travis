**Two:** Travis owns a machine. The mouth stays Travis. The try is the box. An error is the next call on that same machine, same files — not a new ticket and not silence.

## Need side — external systems

Engineer inventory. Not a vendor lock. SA picks the contract or refuses.

**Keep**

- Vercel — the phone. It cannot be the box. The request dies.
- Postgres — rooms, tickets, dest, house rows.
- Cursor Cloud — seated people’s computers. **Not** Travis’s box. Do not reuse `Agent.create` as his disk.

**Must add**

1. **A Linux VM API.** Disk + shell Travis’s tools can call. Candidates that already exist as products: **Fly Sprites** (computer stays, files stay, wakes when we hit it) or **E2B** (spin, run, pause). First founder-named POSIX job was stand a template into a repo — that wants files that survive, which leans Fly. E2B is the “run this and come back” box. Pick one. Do not build a hypervisor.
2. **A server-side key** for that API. Same rule as `CURSOR_API_KEY`. Phone never sees it.
3. **The disk.** Persistent VM → the disk is the VM. Throwaway VM → object storage (R2 / S3) so files outlive the VM. 012 refused S3 for the house. Path two reopens that only if the VM is throwaway.

**Add only if the first job is unfold**

4. **GitHub.** Git on the box plus a token so “stand the seats template into a repo” is a push, not a prompt.

**Do not add this cut**

- Computer use / a browser.
- A second chat product.
- An integrations table. Install stays env (011).
- A third orchestrator server. Vercel calls the VM the same way it calls Cursor.

**How it runs (mechanism)**  
Founder talks. Travis tools hit *his* machine: write a file, run a command, read what came back. If it errors, the next call is that machine, those files. That is the climb-out.
